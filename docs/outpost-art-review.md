## 2. 계약 요청 — 없음 (확인 1건)

`src/outpost/contract.ts`로 R1의 요청이 전부 해소되었습니다. **추가 API를 요청하지 않습니다.** 상하 반전은 `VENT_ROW=0`·`CORE_ROW_ANCHOR=9`로, 방향 예고는 `WaveView.incoming`(`vent`+`strength`)로, 고스트 경로 변화는 `BuildPreview.changedTiles`+`sealsPath`로 충족됩니다. 인셋은 셸이 캔버스 박스를 확정해 넘기므로 렌더러가 알 필요가 없습니다(§4). `discovered`/`unlocked`의 `at`, `automationUnlocked`, `salvageExhausted`도 이미 있습니다.

**확인 1건(문서 오타, 1줄).** `ChapterSpec.layout` 주석이 `9행 × 12줄`인데 실제는 **12줄 × 9열**(문자열 12개, 각 9자)입니다. 그대로 두면 `content.ts` 작성자가 판을 90도 뒤집을 수 있습니다.

## 3. 렌더러 구성 (최종)

캔버스 1 + 오프스크린 2. 아키텍처 §10.1의 L0~L4를 유지하되 **오프스크린을 1장 늘립니다.**

| 레이어 | 갱신 | 내용 |
|---|---|---|
| **S0 배경**(오프스크린 A) | 리사이즈·`chapter` | 격자 **바깥** 해구 벽·수주(§4 여백 밴드). 그리드와 무관 |
| **L0 지형**(오프스크린 B) | `fieldVersion`·`chapter`·리사이즈 | 물 4단 그라디언트, 암반, 열수, 균열, 잔해, 코어 토대, 타일 경계(알파 .06) |
| L1 구조물 | 매 프레임(≤40) | 본체·레벨 실루엣(§6)·HP 바·`aim`·`charge`·열수 발광 |
| L2 유닛 | 매 프레임(적 ≤80) | `prev→pos` alpha 보간. y 정렬 후 그리기 |
| L3 FX | 매 프레임 | `ShotView` 4종, 파티클 ≤160, 플로팅 수치 |
| L4 오버레이 | 입력 시 | 고스트·사거리·경로 화살표·봉쇄 경고(§8) |

- 그림자·발광은 `shadowBlur` 대신 **다중 알파 스택**(반경 ×1/×1.8/×3.2, 알파 .5/.22/.08, `lighter`). `ctx.filter` 금지. `fieldVersion` 변경 시 L0만 다시 굽고 S0은 유지 → 건설 1회당 재굽기 1장.
- 모든 면은 **3단 램프**(하이라이트/기본/그림자) + 광원 반대편 **1px 림라이트**. 이것이 90년대 도형과의 유일한 차이입니다.

## 4. 핏 계산 — 캔버스 박스 안에서만

**렌더러는 HUD를 두 번 빼지 않습니다.** 셸이 HUD 레이아웃을 끝낸 뒤 캔버스의 CSS 박스 `(cw, ch)`를 `resize`로 넘기고, 렌더러는 그 안에 9×12를 전부 넣습니다. 인셋·바 높이·독 높이는 렌더러의 관심사가 아닙니다.

```
tile    = min(floor(cw / 9), floor(ch / 12), 64)   // 하한 클램프 없음 — 넘치게 만드느니 작게 그린다
originX = (cw - tile * 9) / 2                      // 남는 축이 §5 여백 밴드가 된다
originY = (ch - tile * 12) / 2
snapRadius = max(12, tile * 0.55)                  // 타일이 작아질수록 스냅이 커진다
```

| 뷰포트 | 셸이 넘기는 캔버스 박스(권장) | tile | 그리드 | 여백 밴드 |
|---|---|---|---|---|
| **390×844** | 390 × 595 | **43** (폭 제약) | 387×516 | 상하 각 **39.5** — 세로 밴드 |
| 412×915 | 412 × 699 | **45** (폭 제약) | 405×540 | 상하 각 79.5 |
| 360×640 | 360 × 492 | **40** (폭 제약) | 360×480 | 6 |
| 360×640 (독이 큰 경우) | 360 × 456 | **38** — 하한 미달 허용 | 342×456 | 좌우 각 9 |
| **1440×900** | 1048 × 796 | **64** (상한, 원값 66) | 576×768 | 좌우 각 **236** — 가로 밴드 |

- **40px는 목표지 하한이 아닙니다.** 좁거나 낮은 화면에서 38px까지 내려가도 넘치게 하지 않습니다. 정확도는 크기가 아니라 **스냅 반경 + §8의 2단 확정**이 담보합니다 — 작은 것을 누르는 순간은 "선택"뿐이고 "확정"은 항상 48px입니다. 이 규격이면 아키텍처 R5의 9×11 축소는 불필요합니다.
- 데스크톱은 타일 상한 64가 걸려 **가로가 남고**, 폰은 **세로가 남습니다.** 밴드 방향이 축마다 다르므로 S0는 두 방향 모두 채워야 합니다(§5). `tile`은 정수, `origin`은 0.5 단위 반올림, DPR ≤ 2, 캔버스 픽셀 = round(css × dpr).

## 5. 첫 프레임 — 설계된 장면 (점 몇 개 금지)

웨이브 1 건설 단계, 조작 전. 화면에 반드시 보이는 것:

1. **여백 밴드(S0)** — 폰은 위쪽 밴드에 어둠 속으로 사라지는 수주 + 하강하는 마린 스노우, 아래쪽 밴드에 전초기지 기초와 해구 바닥. 데스크톱은 좌우에 층리가 보이는 해구 벽 + 원경 실루엣 2겹. **밴드는 레터박스가 아니라 장면의 일부입니다.**
2. **균열 2곳(위, 0행)** — 상단 암벽의 갈라진 틈. 차가운 청록 발광 + 8초 주기로 느리게 숨 쉼. 여기가 위협의 출처임을 글자 없이 알립니다.
3. **코어 2×2(아래, 9~10행)** — 유일한 따뜻한 광원. 창 4개 순차 점등, 반경 2.5타일 온광 그라디언트가 주변 물을 물들입니다.
4. **잔해 4곳** — 부서진 선체 실루엣 + 회수 가능 반짝임 3점(`richness` 비례).
5. **열수(전방 2~4행)** — 굴절 플룸 + 상승 기포. 코어에서 먼 위험지대에 있다는 것이 위치만으로 읽혀야 합니다(전진 공명기의 대가).
6. **암반 10타일** — 단색 블록이 아니라 층리 3줄 + 이끼 점묘.
7. **잠수정** — 코어 옆 정박, 탐조등 콘(반경 3타일, 알파 .12)이 실제로 지형을 밝힙니다. 정지 화면 금지: 마린 스노우·기포·코어 점멸·균열 호흡은 축소 모션에서만 멈춥니다.

## 6. 적 실루엣과 건물 강화 — 43px에서 읽히는 규칙

| 적 | 크기(타일) | 실루엣 | 움직임 |
|---|---|---|---|
| `drifter` 표류체 | 1.0 | 종 모양 몸통 + 촉수 4 | 느린 맥동 |
| `swarm` 군체 | 0.45 | 뾰족한 삼각 다트, 3~5기 군집 | 불규칙 저크 |
| `breacher` 굴착체 | 1.2 | 낮고 넓은 장갑 쐐기 + 드릴 아가리 | 바닥 밀착, 등딱지 회전 |
| `glider` 부유체 | 0.9 | 만타 날개 | **유일하게 바닥에 그림자를 떨굽니다** — 공중임이 즉시 읽힘 |
| `leviathan` 보스 | 2.6 | 다분절 뱀형, 세로 공간 점유 | 분절 사인파 |

- **정예(`variant: 'elite'`)**: 실루엣 유지 + **셰브런 장갑판 3장 + 바이올렛 림**. 색만 바꾸지 않습니다(장갑 3 = 판 3장으로 수치를 형태로 노출).
- **강화(`level 0..2`)**: 색이 아니라 **부품 수와 높이**로 읽습니다. 발자국은 1타일 고정. 작살 1→2→4 배럴, 박격포 짧은 관→긴 관+차폐→쌍열+장전 드럼, 격벽 1판→2판+가새→버팀벽+앵커, 수집기 팔 1→2+호퍼→회전 드럼, 정비고 도어 1→2→3+착륙등, 공명기 프리즘 1→3→3+헤일로.
- **유한 인양 리저브** — 방치 악용을 막는 장치이므로 **월드에서 보여야** 합니다. `SalvageView.reserveRemaining / reserveTotal` 비율로 잔해의 회수 반짝임이 3→1점으로 줄고, `WreckView.richness`가 0.5에 닿으면 선체가 무광 회색으로 바래며 늑재가 드러납니다. `exhausted`면 네 잔해 모두 발광 정지 + 수집기 본체 채도 0, `salvageExhausted` 이벤트 지점에 1회 링 파문. **"더 캘 게 없다 = 웨이브를 시작할 때다"** 를 HUD 숫자보다 먼저 화면이 말합니다.

## 7. 전략 3종의 한눈 판독 — 면 / 점 / 선 (서로 다른 기하를 점유해 섞어 지어도 충돌하지 않음)

| 전략 | 기하 | 색 | 파티클 |
|---|---|---|---|
| 미로 + 박격포 | **면** — 격벽이 레인을 두껍게 덮음 | 앰버 경계등 | 착탄 먼지, 벽 스파크 |
| 분산 대공 작살 | **점** — 코어 주변에 균일 간격 앵커 | 시안 조준선이 방사형 | 예광 실선 |
| 전방 열수 공명기 | **선** — 열수 타일을 따라 전방으로 뻗음 | 바이올렛 맥동 + 열수 백색 | 방어무시 링 파문 |

## 8. 고스트와 안전 확정 (2단 탭 — 아키텍처 §10.3 준수)

1. 독에서 건물 칩 탭 → 칩이 선택 상태(48px), 지을 수 없는 타일 전체가 알파 .25로 가라앉습니다.
2. 타일 탭 → **고스트**: 실제 크기 본체 알파 .6 + 사거리 원(시안 점선) + `preview.cost` 배지. `preview.result.ok === false`면 붉은 해칭 + `rejectMessage` 한 줄.
3. `preview.changedTiles`를 **점선 화살표 애니메이션**으로 겹쳐 그려 경로가 어떻게 바뀌는지 보여줍니다. `sealsPath:true`면 추가로 붉은 경고 배지 + `changedTiles` 중 코어에 가장 가까운 격벽을 맥동시켜 "막으면 저 벽을 때린다"를 짓기 전에 보여줍니다(계약 추가 없이 근사).
4. **확정 버튼 48px**가 타일 옆(캔버스 안쪽으로 클램프)에 뜹니다. 확정 전 자원 미차감, 다른 곳 탭 = 취소, 모달 없음. 드래그 10px 초과는 잠수정 이동으로 넘기고 고스트는 유지합니다(§10.3 판정과 동일).
