## 2. P0 — 출시 차단

### P0-1. 데스크톱(≥900px)에서 건설 불가 — 확정(코드+화면)

- `src/outpost/outpost.css:136-138` — `@media (min-width: 900px)` 안에서 `.op-dock [data-op='build-strip'] { display: none; }`
- `src/outpost/hud.ts:241-257` — 건설 칩은 `buildStrip`에**만** 붙습니다. `mountPanels()`(`hud.ts:543-556`)가 레일로 옮기는 것은 연구·자동화·해금·발견·퍼크·설정 패널 6개뿐입니다.
- 키보드 대체 경로도 없습니다(`main.ts:424-439`에는 `Esc`/`1`/`2`/`Enter`만 있음).
- 1280×800 스크린샷: 하단 독에는 액티브 2개, 웨이브 시작, 조타만 있고 칩이 없습니다. 그런데 안내 문구는 "작살을 골라 통로에 세우세요"입니다.
- 900px 이상인 태블릿 가로(iPad 1024×768 등)도 같은 증상일 것으로 **추정**합니다(같은 미디어 쿼리).

**수정 방향**: 레일 맨 위에 「건설」 패널로 칩을 옮기거나, 데스크톱에서 칩 숨김 규칙을 지웁니다. 숫자키 `3`~`8` 같은 칩 단축키도 함께 두기를 권합니다.

### P0-2. 캔버스 크기 자기 고정 — 확정(코드), 증상 확정(화면)

- `src/outpost/renderer.ts:124-125`는 `canvas.style.width/height`를 **px 값으로 고정**합니다.
- `src/outpost/main.ts:448-457`의 `resize()`는 **같은 canvas**의 `getBoundingClientRect()`를 측정하고, `ResizeObserver`도 **canvas 자신**을 관찰합니다.
- 인라인 px 크기가 CSS의 `inset:0; width:100%`를 이기므로, 월드 박스가 바뀌어도 canvas 크기는 그대로입니다. Observer도 발화하지 않고, 창 `resize` 이벤트가 와도 고정된 값을 다시 읽을 뿐입니다. **첫 측정값이 영구히 유지됩니다.**
- DOM 덤프 결과:
  - 뷰포트 414×896: `<canvas width="500" height="622" style="width: 500px; height: 622.312px">`. 캔버스가 뷰포트보다 넓습니다.
  - 1280×800: `896×585`. 월드 영역은 약 912×679이므로 아래쪽에 약 95px 검은 띠가 생깁니다.
- 스크린샷(dev·prod 모두): 360/414 폭에서 그리드 오른쪽 열이 잘리고, 독 위에 검은 띠가 보입니다.
- **가설(실기기 확인 필요)**: 폰을 회전하거나, 모바일 주소창이 접히거나, 데스크톱 창 크기를 바꾸면 판이 원래 크기에 머뭅니다. `pickTile`은 layout 기준이라 그림과 탭이 일관될 수는 있지만, 판의 일부는 보이지 않는 영역에 남습니다.

**수정 방향**: 측정 대상을 `.op-world`(부모)로 바꾸고 Observer도 부모에 겁니다. 렌더러는 백버퍼(`canvas.width/height`)만 설정하고 CSS 크기는 쓰지 않습니다.

### P0-3. 좁은 폰에서 하단 행·상단 리본 넘침 — 확정(화면)

- 414×896과 360×640 스크린샷: 하단 행 `[소나][용접][웨이브 시작][조타][패널]` 중 **「조타」가 잘리고 「패널」은 화면 밖**입니다. 상단 리본의 코어 게이지도 오른쪽에서 잘립니다.
- 원인(코드 근거, 부분 가설):
  - `.op-btn { min-width: 48px }`(`outpost.css:229-231`)와 `.op-ability { flex: 1 }`가 겹칩니다.
  - 긴 시작 버튼 라벨 "웨이브 1 시작 · 조기 +9초"가 들어갑니다.
  - 리본은 `.op-stat min-width 58px` ×3과 `.op-salvage min-width 92px` ×2(`outpost.css:150-182`)를 합쳐 약 420px로, 360px보다 넓습니다.
- 「소나 충격파」 라벨이 두 줄로 줄바꿈되면서 「준비」 표시와 겹칩니다(360px).
- P0-1과 합치면 **폰에서는 설정·연구가 불가능하고 데스크톱에서는 건설이 불가능**합니다.

**수정 방향**: 행을 두 줄로 나누거나(액티브 2 / 시작·조타·패널), 「패널」을 리본 오른쪽 아이콘으로 옮깁니다. 시작 버튼 라벨은 "시작 +9초"로 줄입니다. 리본 min-width는 합이 뷰포트를 넘지 않게 조정합니다.

### P0-4. 초기화가 영구 진행을 지우고, 확인도 없음 — 확정(코드)

- `hud.ts:465` 문구는 "통찰과 발견은 유지됩니다"입니다.
- `hud.ts:474`: 버튼 클릭 한 번에 곧바로 `emit({ kind: 'restart' })`.
- `main.ts:465-472`: `removeLocal(SAVE_KEY_RUN)` 후 `createSim({ save: null })`.
- `contract.ts:562`, `save.ts:77-88`: `meta`(통찰·퍼크·발견·best)가 **같은 `outpost-run-v1` 봉투** 안에 있습니다. 그래서 초기화하면 메타도 함께 사라집니다.
- 승리 모달의 「새 캠페인」(`hud.ts:936`)도 같은 경로입니다. **캠페인을 끝낸 보상(통찰)이 새 캠페인 시작과 동시에 사라집니다.**
- 데스크톱에서는 설정 패널이 레일에 항상 펼쳐져 있어 오클릭 가능성이 더 큽니다.
- 테스트 `'런만 깨지면 메타(통찰·발견·퍼크)는 살아남는다'`는 **파싱 실패** 경로만 다룹니다. 셸의 restart는 검증하지 않습니다.

**수정 방향**: 새 캠페인은 `createSim({ save: 메타만 유지한 봉투 })`로 만듭니다(sim에 `newCampaign` 명령을 추가하거나, 셸이 `meta`만 보존). 초기화는 2단 확인(길게 누르기 또는 확인 시트)으로 바꿉니다. 문구와 동작 중 하나는 반드시 일치시킵니다.

## 3. P1 — 높음

### P1-1. 일시정지 없음, 시트가 전장을 덮음 — 확정(코드)

- `src/outpost` 전체에 `pause` 문자열이 0건입니다. `outpost-decisions.md` C11("일시정지·2배속 — 셸이 `step()` 호출 횟수로 제어")이 미구현입니다.
- 모바일 시트는 `position: fixed; inset: 0; z-index: 40; background .97`(`outpost.css:597-607`)입니다. 웨이브 중 「패널」을 열면 **전장이 완전히 가려진 채 시뮬이 계속 돕니다**(`main.ts:490-516`은 모드와 무관하게 `advance`).
- 안전한 부분(확정): 탭이 숨겨지면 rAF가 멈추고 `dt`는 0.25초로 잘리며, 숨김 시 저장합니다. 백그라운드 전환만으로 폭주하지는 않습니다.
- 가설: 데스크톱에서 창이 보이는 채로 포커스만 잃으면(다른 창 클릭) 게임은 계속 진행됩니다.
- 참고(확정, 테스트 이름 근거): 웨이브 도중 새로고침하면 그 웨이브 시작 상태로 돌아갑니다. "새로고침 = 되감기"라서 일시정지 대신 쓰일 수 있고, 발견과 해금을 반복 시도하는 데 쓰일 여지가 있습니다(가설).

**수정 방향**:
- 셸에 `paused`를 두고, 켜져 있으면 `sim.advance`를 건너뜁니다.
- 웨이브 중 시트가 열리거나 `blur` 이벤트가 오면 자동으로 일시정지합니다.
- 일시정지 버튼과 오버레이는 리본에 둡니다.
- 일시정지 중에도 건설·연구 명령을 허용할지 결정해야 합니다(권장: 허용. 계획형 방어의 핵심 쾌감).

### P1-2. 강화·판매 어포던스 — 확정(코드)

- 컨텍스트 트레이(`hud.ts:494-505`)의 버튼 라벨은 고정 문자열 「강화」「판매」뿐입니다. 비용은 `upgradeCost()`(`sim-state.ts:469`, 레벨당 ×1.8), 환급은 `investedScrap × 0.5`(`sim.ts:286`)인데, 어느 값도 HUD에 표시되지 않습니다.
- 강화 비활성화 조건은 최대 레벨뿐입니다(`hud.ts:663`). 자원이 부족해도 버튼이 활성으로 보이고, 누른 **뒤에야** 거부 토스트가 뜹니다. 건설 칩에는 `data-afford`로 빨간 비용이 뜨는 것과 일관되지 않습니다.
- 강화 후 수치 변화(피해·사거리·HP ×1.55)를 미리 볼 수 없습니다. 아트 문서가 약속한 "부품 수 증가" 외에는 숫자 근거가 없습니다.
- 판매는 확인이 없고, 성공 즉시 선택이 해제됩니다(`hud.ts:531-535`). 트레이 버튼 3개가 48px로 붙어 있어 「강화」와 「판매」 사이 오터치가 가능합니다(가설: 실기기 오터치율 측정 필요).
- 판매 가능 단계에 웨이브가 포함되고, 환급이 HP와 무관합니다(`sim.ts:280-293`) → P2-4.

**수정 방향**:
- 버튼 라벨을 「강화 고철 81」「판매 +22」로 바꿉니다.
- 강화 버튼에 `affordability`를 적용합니다.
- 강화 미리보기 한 줄을 추가합니다("피해 9→14 · HP 120→186").
- 판매는 2단 탭(첫 탭에서 「+22 확정?」으로 바뀜)으로 만듭니다.
- 판매 버튼을 강화 버튼과 떨어뜨립니다.

### P1-3. 위협 카드가 분출구를 가림 — 확정(코드+화면)

- `.op-topinfo`는 월드 위 `top:6px` 절대 위치입니다(`outpost.css:406-415`, 입력만 통과). 위협 카드와 안내 문구를 합쳐 높이가 약 80px입니다.
- 스크린샷: 1280×800과 414×896 모두 0~1행(분출구)이 카드 아래에 있습니다. 360×640에서는 판이 작아 약 2행이 가려집니다.
- 건설 단계에서 "어디서 오는가"를 읽어야 할 순간에 가장 중요한 행이 가려집니다. 안내 문구는 웨이브 중에도 계속 떠 있습니다(`hud.ts:776`).

**수정 방향**: 위협 카드를 독 위 또는 시작 버튼 옆으로 옮기거나, 판 위쪽 여백 밴드(bandY)가 있을 때만 그 안에 둡니다. 안내 문구는 N초 뒤 접히게 합니다. `fitView`에 `insets.top`을 실제 오버레이 높이로 넘기는 방법도 있습니다(계약이 이미 지원).

### P1-4. 통찰 경제가 보이지 않고 닿지 않음 — 확정(코드·산술)

- 리본에는 고철·생체·웨이브만 있습니다(`hud.ts:151-162`). `.op-stat[data-tone='insight']` CSS는 있지만 셀이 없습니다. 통찰은 퍼크 버튼 비활성화 판정(`hud.ts:877`)에만 쓰입니다.
- 공급(`content.ts:435`): 웨이브 첫 클리어 1 ×8 + 발견 3 ×3 + 장 진입 8 = **최대 25**.
- 수요(`content.ts:427-429`): (5+8+6) × 3레벨 = **57**.
- P0-4 때문에 새 캠페인에서 통찰이 0으로 돌아가므로, **퍼크 트리는 어떤 플레이로도 절반 이상 채울 수 없습니다.**
- `meta.best`(최고 웨이브·시간)는 저장되지만 HUD 어디에도 표시되지 않습니다(`hud.ts`에 `best` 참조 0건).

## 4. P2 — 중간·낮음

- **P2-1 조기 보너스 vs 무시간 건설**(확정/설계 판단): `earlyBonusSeconds: 10`(`content.ts:535`). 첫 화면부터 시작 버튼이 "조기 +9초"를 셉니다(`hud.ts:837-841`, 스크린샷). 결정 문서 §2의 "건설 단계는 시간 제한이 없다"와 정신이 충돌하고, 가장 생각이 필요한 W1·W4·W5에서 읽기를 벌합니다. **권장**: 보너스 조건을 시간 대신 "리저브를 X% 남기고 시작"으로 바꾸거나, 첫 장에서는 끕니다.
- **P2-2 건설 모드에서 건물 선택 불가**(확정): `main.ts:414-420`. 칩이 선택된 상태에서는 모든 타일 탭이 고스트가 됩니다. 기존 건물 탭은 "점유됨" 거부로 끝납니다. **권장**: 점유 타일 탭은 건설 모드를 끝내고 그 건물을 선택합니다.
- **P2-3 키보드가 상태 무시**(확정): `main.ts:424-439`. 패배·승리 모달이나 시트가 열려 있어도 `1`/`2`로 조준 모드에 들어가고, `Enter`로 확정됩니다. 입력 요소 포커스도 검사하지 않습니다.
- **P2-4 판매 환급이 HP와 무관**(확정): 웨이브 중 부서지기 직전 벽을 팔면 50% 회수이고, 부서지면 0%입니다. 의도된 전술일 수도 있으므로 **디자인 판정이 필요**합니다. 막으려면 `refund × hp/maxHp`를 적용합니다.
- **P2-5 레일 잘림**(확정-화면): 1280px에서 자동화 「드론 역할」 세그먼트의 「혼합」 버튼이 레일 오른쪽에서 잘립니다.
- **P2-6 첫 프레임 「작살 해금」 라벨**(화면 확정, 원인 가설): HUD는 첫 동기화 이벤트를 replay로 억제하지만(`hud.ts:745-751`), 렌더러는 억제 경로가 없어 초기 `unlocked` 이벤트를 월드 라벨로 그리는 것으로 보입니다.
- **가설 H1 드래그 임계 10px**: `main.ts:37`. 고밀도 터치에서 탭이 10px 넘게 흔들리면 조용히 잠수정 이동으로 바뀌고 고스트 배치가 무시됩니다. 실기기에서 오터치율을 측정해야 합니다(게임리뷰 수락 #1 "오터치 0/10").
- **가설 H2 재시작 후 HUD 잔여 상태**: `restart()`는 sim만 교체합니다. HUD의 `firstSync`/`newlyUnlocked`/`announcedOffline`은 초기화되지 않아, 새 sim의 초기 이벤트가 배너로 뜨거나 "신규" 반짝임이 남을 수 있습니다.
- **가설 H3 확정 버튼 위치 고정**: `hud.ts:691-692`가 확정 행을 항상 `left:50%; bottom:64px`에 둡니다. 판 하단 중앙은 코어(9~10행) 부근이라, 그 주변 타일을 고르면 **✓✕가 고스트 자체를 가릴 수 있습니다.** 아트 리뷰 §8은 "타일 옆"을 약속했습니다.
