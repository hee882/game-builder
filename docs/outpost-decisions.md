## 2. 안전 건설 단계와 유한 인양 리저브 (핵심)

건설 단계는 **시간 제한이 없다**. 그래서 무한 수입이 되지 않게 **인양 리저브**로 막는다.

- 웨이브 사이클마다 리저브가 배정된다: `reserve(w) = 70 + 20 × (w − 1)` → W1 70 … W8 210 (캠페인 합 **1,120**). R3 시뮬레이션에서 2,460은 작살 도배를 허용해 배치가 무의미해졌다(§9).
- 잠수정 수동 인양(5.5/s) · 수집기(3.2/5.0/7.7/s) · 인양 드론(3.3/s)의 **모든 고철 수입이 이 리저브에서 차감**된다.
- **리저브 0 → 인양 수입 0.** 카운트다운 대신 "리저브 고갈"이 웨이브를 시작할 신호다. `salvageExhausted` 이벤트 + 거부 이유로 알린다.
- **남은 리저브는 다음 사이클로 넘어가지 않는다**(사이클마다 재배정). 건설 단계를 오래 끌어도 얻는 것이 없다.
- **오프라인 정산도 리저브 상한 안에서만**: `min(경과 7,200초 × 40% 효율 × 자동 수입, 남은 리저브)`. 웨이브는 진행하지 않는다. 미래·음수 타임스탬프는 0.
- HUD는 **남은 리저브와 배정량을 항상 표시**한다(`SalvageView.reserveRemaining / reserveTotal`). 고갈 시 수집기 아이콘이 회색으로 바뀐다.
- 전투 보상(생체물질·웨이브 고철)은 리저브와 무관하다 → **손을 쓰는 쪽이 상한이 없다.**

## 4. 실제로 성립하는 전략 3종

| | **미로 + 박격포** | **분산 작살 대공망** | **전진 열수 공명기** |
|---|---|---|---|
| 재료 | 격벽 다수 + 초크에 박격포 | 작살 6~8기를 1타일 이상 띄워 배치 | 전방 열수(1장 행 2 / 2장 행 3)에 공명기 + 전방 격벽 |
| 이기는 방식 | 경로를 늘려 폭발로 태운다 | 공중·지상 모두 끊김 없이 맞춘다 | 스폰 직후에 녹이고 전방 잔해(×1.6)로 돈을 번다 |
| 약점 | 부유체(벽 무시, W4·W6) · 굴착체(벽 비용 낮음, W3·W5·W7) | 군체 대량(W2·W6 정예 16) · 정예 장갑 3이 작살 9 → 6 | 전방 구조물이 먼저 맞는다 · 보스 벽 피해 60 dps |
| 강제되는 보완 | 코어 근처 대공 작살 | 박격포(광역) 또는 관통 작살 테크 | 후방 2선 + 정비 드론 |

어느 하나만으로 W8을 깨지 못한다. 웨이브 표가 셋을 번갈아 처벌한다(W4 부유체 → 미로, W5 정예 장갑 → 작살, W7 전방위 3분출구 → 전진).

## 5. 실패와 재시도 (초반 재반복 금지)

코어 HP 0 → `phase: 'defeat'`. `retryWave` 1회 명령으로 **실패한 그 웨이브를 다시** 한다.

- 복원: **웨이브 시작 시점 배치**(`RunSave.waveStartBuildings`)를 전부 HP 만땅으로 되돌린다.
- 지급: **재건 예산 고철 `120 + 40 × 재시도횟수`** + 해당 웨이브 리저브 재배정.
- 유지: 발견 · 테크 · 통찰 · 퍼크 · 건물 해금 · 최고 기록(`RetryView.keepsDiscoveries: true`가 계약으로 고정).
- 없음: 보상 감소, 압력 −2식 벌점, 재시도 횟수 제한, 이전 장 재플레이. **1장으로 되돌리지 않는다.**
- 부분 실패: 한 웨이브 누수 4회 이상이면 누수 경로 4타일이 2웨이브 동안 `flooded`(그 위 구조물 파괴) → 배치를 다시 짜게 만드는 중간 실패.
- 자동 저장은 웨이브 정산·건설 확정·백그라운드 전환 시점. 웨이브 도중 새로고침은 **그 웨이브 시작 상태**로 복귀한다.

## 6. 동결된 파일 경로·소유권

```
src/outpost/contract.ts   ← 이 라운드 산출물(동결). 변경은 코디네이터 경유 + 필드 추가만
src/outpost/content.ts    건물·적·웨이브·레이아웃·EconomyTuning 상수 (BUILDING 카탈로그 메타데이터 포함)
src/outpost/path.ts       가중 벽 돌파 Dijkstra 흐름장(ground/breaker/flyer)
src/outpost/save.ts       MetaSave/RunSave 직렬화 + 엄격 검증
src/outpost/sim.ts        createSim — 고정 1/30초 스텝, 시드 PRNG, DOM·Date·Math.random 금지
src/outpost/renderer.ts   createRenderer — Canvas 2D 레이어·오프스크린 캐시
src/outpost/layout.ts     순수 좌표·스냅·컬링 수학(노드 테스트 가능)
src/outpost/hud.ts        DOM HUD(변경분만 갱신)   src/outpost/format.ts  한국어 라벨·숫자(순수)
src/outpost/main.ts       부트스트랩·입력·오디오·rAF·localStorage   src/outpost/outpost.css
outpost.html              새 Vite 엔트리(기존 3엔트리 무수정)
```

- `createSim`은 `sim.ts`, `createRenderer`는 `renderer.ts`에만 존재한다(계약은 시그니처 타입 `CreateSim`/`CreateRenderer`만 제공).
- 단방향 의존: `main → hud → format → contract`, `main → renderer → layout → contract`, `main → sim → {content, path, save} → contract`.
- UI는 `issue()`와 읽기 전용 `preview()`·`view()`·`drainEvents()` 외의 경로로 상태를 바꾸지 않는다. `drainEvents()`는 `main.ts`가 프레임당 1회.
- **저장 관례(확정)**: `sim.serialize()` 결과 **하나**를 `SAVE_KEY_RUN = 'outpost-run-v1'`에 쓴다(메타 + 런을 담은 `OutpostSave` 봉투). 설정은 셸이 `outpost-settings-v1`, 마지막 저장 시각은 `outpost-saved-at-v1`에 따로 보관한다 — 그래서 `MetaSave`에 `settings`가, `RunSave`에 `savedAtMs`가 **없다**. 별도 메타 키는 쓰지 않는다.
- **content.ts export 이름 고정**: `BUILDINGS` · `ENEMIES` · `VARIANTS` · `WAVES` · `CHAPTERS` · `TECHS` · `PERKS` · `ECONOMY` (스키마는 계약의 `BuildingCatalog`·`EnemyCatalog`·`VariantTable`·`WaveSpec[]`·`ChapterSpec[]`·`TechCatalog`·`PerkCatalog`·`EconomyTuning`).
- 이번 라운드 범위 밖: 시뮬·렌더러 구현, 레이아웃 문자열, 밸런스 튜닝 실행, git 작업.

추가로 드러난 규칙 두 가지(구현 사실, 문서화 목적):
- **잔해 타일은 건설 불가이면서 통행 가능하다** → 잔해가 있는 행(1장 행 3·7)은 어떤 배치로도 완전 봉쇄할 수 없다. 천연 초크(행 6)만 5장으로 봉쇄 가능하다.
- **잠수정 위치는 `RunSave`에 없다** → 복원 시 코어에 정박한 상태로 시작한다(계약 추가 없이 유지).
