아키텍처 §5 계약과 §6 경제는 그대로 구현 가능합니다. 게임디자인 관점에서 **반드시 고쳐야 할 것은 3가지**입니다.

## 3. 유한 잔해 매장량 (P1 해결) — 무시간 건설 단계를 안전하게 만드는 장치

`richness` 감쇠(시간 압박)를 폐기하고 **웨이브당 고정 매장량**으로 바꿉니다. 건설 단계에 타이머가 없어도 무한 성장이 불가능해집니다.

- 웨이브 n의 잔해 매장량 `reserve(n) = 150 + 25 × (n − 1)` 고철. 잔해 타일 5개에 균등 분배.
- 수동·수집기·드론이 **같은 풀에서 인출**합니다. 풀이 0이면 **수입이 완전히 멈춥니다**(잔해가 시각적으로 꺼짐 + 「이번 분출 잔해 고갈」 1줄).
- 풀은 **웨이브 클리어 시에만** 다음 값으로 재충전됩니다(잔해 낙하 연출 = 성장 신호).
- **수동 우위를 총량이 아니라 회수율로 재정의**합니다 — 유한 풀에서는 초당 속도 차이가 "먼저 끝날 뿐"이 되어 우위가 사라지기 때문입니다.

| 인출 주체 | 회수율 | 8웨이브 누적 최대 |
|---|---|---|
| 잠수정 수동 | **100%** | 1,900 |
| 수집기 | 80% (강화 시 88 / 95%) | 1,520~1,805 |
| 인양 드론 | **65%** (`droneLogistics` 78%) | 1,235~1,482 |

전부 방치해도 약 65%를 얻어 진행은 되고, 손을 쓰면 최대 1.54배까지 벌립니다. 이것이 아키텍처 §6.2의 «수동 우위»를 유한 경제 안에서 유지하는 방법입니다. 테스트는 "수동 누적 > 수집기 누적 > 드론 누적"과 "풀 고갈 후 5분 대기해도 고철 증가 0"을 단정합니다.

## 4. 전략 3종 — 코디네이터 확정안의 구체화

| | **S1 미로+박격포** | **S2 분산 대공** | **S3 전방 열수 공명** |
|---|---|---|---|
| 핵심 | 격벽으로 통행 비용을 키워 박격포 사거리 4.0 안 **체류 시간 최대화** | 작살을 경로 전역·코어 주변에 **넓게 분산**, 벽 투자 최소 | 열수 타일 위 공격 건물 2기 → `ventResonance` → **공명기(방어 무시)** 를 분출구 쪽 전진 배치 |
| 타일 점유 | 굵은 벽 띠 + 박격포 2~3 | 벽 적음, 터렛 8~10 분산 | 열수 타일 중심 소수 밀집 + 전방 |
| 강함 | W2·W3 (지상 물량) | W4·W6 (공중) | W5·W6 (정예 장갑) |
| **무너지는 지점** | **W4 부유체** — 벽 무시 + 박격포 지상 전용 | **W5 정예 장갑 3** — 작살 −33% | **W7 3분출구** — 전방 구조물이 먼저 집중 피격 |
| 시각 판독(아트 §9.4) | 면(두꺼운 벽) | 점(퍼진 터렛) | 선(열수 발광 축) |

카운터가 바뀌는 축이 **이동(벽 무시) → 방어(장갑) → 위상(다방향)** 으로 서로 다르기 때문에, 한 전략을 강화하는 투자가 다음 웨이브에 재사용되지 않습니다. 이것이 "반복적이지 않음"의 구조적 근거입니다.

## 5. 장갑이 전략을 삭제하지 않게 (제 R1의 실패를 반복하지 않는 규칙)

제 R1 초안은 정액 방어 −6이 DoT 4를 **0으로 만들어** 한 전략을 삭제했습니다. 동일 사고를 막는 콘텐츠 규칙을 `content.ts`에 고정할 것을 권합니다.

- **피해 하한 규칙**: 정액 감소 적용 후 피해는 **기본값의 60% 아래로 내려가지 않습니다.** 작살 9→6(−33%)은 통과, 어떤 미래 장갑 값도 무기를 0으로 만들 수 없습니다.
- 장갑 3은 **S2를 −33%로 약화**시키되 관통 테크(30 생체) 또는 공명기라는 **두 갈래 해답**을 남깁니다. 해답이 하나뿐이면 그것은 카운터가 아니라 강제입니다.
- 정예 도입(W5)은 **해답 해금(W3 드론정비고/생체 축적)보다 뒤**여야 합니다. 현재 표는 이 순서를 만족합니다.

## 7. 눈에 보이는 마일스톤 (성장 체감 지점)

25초 첫 작살 → W2 박격포 **칩이 새로 나타남** → W3 드론이 화면을 돌기 시작(위임의 시각화) → W4 대공 앵커 점등 → **1장→2장 팔레트·레이아웃 동시 전환** → `ventResonance` 발견 연출(공명기 카드 추가) → W8 보스 실루엣. 각 지점은 **새 아이콘이 화면에 등장**하는 형태여야 하고, 숫자만 오르는 마일스톤은 인정하지 않습니다.

## 8. 실패·재시도 (P2·P3 해결)

- 코어 0 → `stageFailed`. **런 초기화가 아니라 해당 웨이브 재시작**입니다.
- **유지**: 발견·테크·퍼크·통찰·자동화 설정·살아남은 건물. **손실**: 해당 웨이브 보상, 파괴된 건물. **보정**: 코어 HP 100 복구, 매장량 1회 재충전, 3회 연속 실패 시 다음 시도 코어 +20.
- 재시도 횟수 제한 없음. 설계도(`placeBlueprint`)는 이 모델에서 역할이 사라지므로 **명령 유지 여부를 코디네이터가 판단**해야 합니다(§10-C7).
- 침수(누수 4회 → 4타일 2웨이브 건설 불가)는 **유지**합니다. 런을 잃지 않으면서 레이아웃을 다시 짜게 만드는 유일한 중간 압박이고, 위 재시도 모델과 겹치지 않습니다.
- `deepArchaeology` 조건을 「수동 인양 누적 400」에서 **「웨이브 진행 중 잠수정으로 잔해 1개를 완전 고갈시키기」** 로 교체합니다. 카운터 채우기가 아니라 한 번의 판단이 됩니다.

## 9. 브라우저 수락 체크 12개 (플레이어 이해도 중심)

아키텍처 §14.2(22개, 기능 위주)와 중복되지 않는 **"플레이어가 이해했는가"** 판정입니다. 각 항목은 안내 문구 없이 성립해야 합니다.

1. 첫 60초 안에 안내 없이 **작살 1기를 의도한 타일에** 세운다(2단 확정, 오터치 0/10).
2. 잔해 매장량이 0이 되는 순간 **수입 정지를 화면에서 읽고**(바 + 잔해 소등) 웨이브를 시작한다 — "버그인가?" 질문이 나오지 않는다.
3. 손을 떼고 3분 방치해도 고철이 유한 상한에서 멈춘다(무한 선행 성장 불가).
4. 「웨이브 시작」 전에 **다음 웨이브 예고 카드를 보고 배치를 바꾼다**(W4 예고 후 대공 추가 관찰).
5. 격벽 고스트에서 **경로 Δ초와 사거리 원을 보고** 확정 전에 위치를 한 번 이상 수정한다.
6. W3에서 굴착체가 벽을 부수고 통과하는 것을 보고 **2선 배치로 스스로 전환**한다.
7. W4에서 박격포가 회색으로 바뀌고 부유체가 벽 위를 지나가는 것을 보고 **원인을 말로 설명**할 수 있다.
8. W5에서 `9→6` 감소 수치를 보고 **관통 테크 또는 열수 배치 중 하나를 선택**한다(둘 다 유효).
9. 열수 타일 위에 두 번째 공격 건물을 세우는 순간 **안내 없이** 발견 연출이 뜬다.
10. 코어 파괴 후 **같은 웨이브가 재시작**되고 발견·테크가 그대로 있는 것을 결과 화면에서 확인한다.
11. 액티브를 정밀 창에서 눌렀을 때와 아닐 때가 **이펙트·수치로 다르게 보이고**, 쿨다운 중 입력은 토스트로 거부된다.
12. 360×640에서 타일 ≥40px·확정 56px·본문 ≥13px이 지켜지고, 잠수정 스틱이 하단 독을 가리지 않는다.

| C4 | `GhostState.sealsPath` → `pathDeltaSeconds`(가중 벽 모델에는 봉쇄가 없음) | I4 |
| C5 | `AbilityView`에 `gauge`, `perfectWindow` 노출 | I8 정밀 게이지 렌더 |
| C6 | `SimEvent`에 `reserveDepleted` / `reserveRefilled` / `stageFailed`(→ `collapsed` 대체) | §3·§8 연출 |
| C7 | `placeBlueprint` 명령 유지 여부 결정 | 스테이지 재시도 모델에서 역할 소멸 |
| C8 | `content.ts`에 **피해 하한 60% 규칙** 상수화 | §5 — 장갑이 전략을 삭제하는 사고 방지 |

C1~C6은 **추가만** 하므로 아키텍처 §16의 "계약은 추가만 허용" 규칙 안에서 처리 가능합니다. C4만 필드 교체입니다.

## 11. 제 R1 초안에서 철회하는 것

전력 흐름 자원과 송전 반경(전력망 폐기) · 숙련 클릭 카운터 자동화(금지) · Phaser 렌더(Canvas 2D 확정) · 조류 압력과 조기 소집 패널티(무시간 건설 단계 + 조기 시작 보너스로 대체) · 9×14 그리드(9×12) · 건물/적 명칭 전반(아키텍처 ID 채택). `docs/outpost-game-design.md`는 R1 기록으로 남기고, **구현 기준은 아키텍처 문서와 이 검토서**입니다.
