## 0. 결론 먼저

지금 게임은 **이기려고 기지를 키울 필요가 없다.** 기지는 작게 머물고, 2장에 들어가면 지워진다. 숨은 발견 3개 중 새 행동을 여는 것은 1개뿐이다.

추천하는 다음 개선: **「전선 확장」 마일스톤.** 세 조각을 순서대로 구현한다.

## 4. 구현 사양

공통 원칙: **계약은 추가만 한다**(결정 §6). 수치는 `content.ts`에만 둔다. 시뮬은 DOM·Math.random·Date를 쓰지 않는다. 한 조각이 한 커밋 묶음이다.

### 4.1 [1순위] 장 이월 키트

**규칙**
1. `advanceChapter`에서 1장 건물 각각을 `{id, level}` **키트**로 바꿔 `state.kits`에 넣는다. 고철 환급(`CHAPTER_RELOCATION_REFUND`)은 **폐지**한다.
2. 새 명령 `placeKit {tile, building, level}`로 키트를 놓는다. 비용 0이고 `validateBuild`의 지형·열수·잔해 인접·(2순위 적용 시) 조명 검사를 그대로 통과해야 한다. 성공하면 키트 1개를 소모한다.
3. 놓은 키트의 `investedScrap`은 `investedFor(id, level)`(F3 수정에서 도입)이다. 판매 환급은 기존 50% 규칙을 따른다.
4. 남은 키트는 2장 내내 유지되고 저장된다. 웨이브 시작 스냅샷(`waveStartBuildings`)과 F1 수정의 «웨이브 시작 자원»에 **키트 목록도 포함**한다. 그래야 재시도·새로고침으로 키트가 복제되지 않는다.
5. 튜닝 손잡이: `CHAPTER_KIT_LIMIT`(기본 무제한). 2장이 쉬워지면 «상위 N개만»으로 줄인다.

**보이는 것**: 2장 첫 프레임에 HUD 독에 **키트 트레이**(아이콘 × 개수, 레벨 점)가 나온다. 칩 대신 키트를 고르면 고스트 비용 배지가 «무료»로 표시된다. 장 전환 모달 문구는 «기지를 분해해 가져갑니다 — 키트 N개»로 바꾼다.

**계약 추가**
- `SimCommand |= { kind: 'placeKit'; tile: TileIndex; building: BuildingId; level: number }`
- `SimView.kits: readonly { id: BuildingId; level: number; count: number }[]`
- `RejectReason |= 'noKit'`
- `RunSave.kits?: { id: BuildingId; level: number }[]`(없으면 `[]`. 스키마 버전은 유지하고 `save.ts` 화이트리스트·클램프에 추가)

**파일**: `contract.ts` · `content.ts` · `sim.ts`(issue/validate/snapshot/restore/view) · `sim-economy.ts`(advanceChapter, retryWave) · `save.ts` · `hud.ts` · `format.ts` · 테스트

### 4.2 [2순위] 조명 전선 + 기지등 (핵심)

**의도**: 성장을 «숫자»가 아니라 **어둠이 걷히는 면적**으로 보여 준다. 동시에 «어느 방향으로 넓힐까»가 매 웨이브의 배치 결정이 된다. 전방 잔해(×1.6)·전방 열수(공명기)라는 기존 유인에 **실제 비용**이 붙고, 남는 고철을 흡수한다.

**규칙**
1. 타일은 `lit`이거나 아니다. **지을 수 있는 곳 = 조명 안**이다. 강화도 조명 안에서만 된다.
2. 조명원은 두 가지다. ① 코어: **행 ≥ `FRONTIER_START_ROW`(6)** 전체. 1장·2장 모두 시작 잔해·중앙 열수 (4,8)·(1,8)·(7,8)과 초크 행 6이 포함된다. ② **기지등**: 타일 중심에서 유클리드 반경 `BEACON_LIGHT_RADIUS`(2.5) 안.
3. **기지등은 조명 안에만 지을 수 있다** → 연쇄로만 전진한다. 기지등은 1×1이고 비용은 고철 35, HP 80, 공격하지 않는다. 시작부터 해금된다(W1 끝에 첫 확장을 체험하게 한다).
4. **조명은 기능 조건이 아니다.** 조명 밖에 남은 건물(기지등 파괴 후 등)도 **계속 작동**한다. 새 건설·강화만 막는다. → 결정 C7이 폐기한 «전력망 붕괴 연쇄»를 다시 들이지 않는다. 흐름 자원·소비·과부하도 없다.
5. 잠수정의 수동 인양은 조명과 무관하다. **전방 잔해는 처음엔 손으로만 캔다.** 수집기로 자동화하려면 전선을 거기까지 밀어야 한다(«풀린 잡무 자동화»가 공간 확장과 연결된다).
6. 조명은 건물 집합에서 **파생**한다. 저장 필드를 추가하지 않고, `restore` 후 다시 계산한다. `litVersion`은 기지등이 추가·파괴·판매될 때만 올린다.
7. 기지등 위협(G7 대응): 기지등이 경로 위에 있으면 기존 규칙대로 부서진다. 경로 밖 기지등은 안전하다. 이번 조각에서 새 적 AI는 넣지 않는다. 부서지면 확장 영역을 잃는 대가만으로 충분한지는 §6 위험에서 계측한다.

**보이는 것**
- L0 지형 굽기에 **어둠 마스크**를 합성한다. 조명 밖은 `ink.abyss` 알파 0.82로 덮는다(아트 디렉션 §18 669행에 이미 명세됨). `litVersion`이 바뀔 때만 다시 굽는다.
- 기지등 고스트: 반경 원과 **새로 밝아질 타일의 윤곽**을 확정 전에 표시한다. 확정 시 `frontierExpanded` 이벤트로 방사형 드러남 연출(0.6초)을 재생한다.
- 조명 밖 타일을 탭하면 `unlit` 거부 토스트 «빛이 닿지 않습니다 — 기지등을 먼저 세우세요»가 뜬다.

**계약 추가**
- `BuildingId |= 'beacon'`(→ `BUILDINGS`·`BUILDING_LABELS`·`render-shapes` 분기 필수. 기존 `label tables cover every id` 테스트가 누락을 잡는다)

### 4.3 [3순위] 발견 → 수문 격벽

**규칙**
1. `flawlessPair`의 보상을 **수문 설계도**로 바꾼다(`UnlockRule { kind: 'discovery', id: 'flawlessPair' }`). 보상 문구 «정밀 사격»은 삭제한다.
   - 조건 조정을 권장한다. 지금은 W1·W2에서 거의 자동으로 달성된다(§2.1). **W3 이후** 연속 2웨이브 무손실로 바꿔 «숨은» 성격을 되살린다. 코디네이터가 결정한다.
2. 수문은 1×1, 고철 30 + 생체물질 10, HP 150이다. **닫힘** = 격벽과 같다(`walls=1`, 부수고 지나감). **열림** = 통행 가능한 빈 물이다(`walls=0`, `structures=0`, 부서지지 않음).
3. 새 명령 `toggleGate {tile}`은 build·wave 단계 모두에서 허용한다. 수문마다 쿨다운 `GATE_TOGGLE_COOLDOWN`(6초)이 있다. **지상 적이 그 타일 위에 있으면 닫기를 거부**한다(`tileOccupied`).
4. 토글 시 `markFieldDirty` → 다음 스텝에 흐름장을 재계산한다(108칸 × 지상 비용 클래스 4개. 비용은 무시할 만하다).
5. 스냅샷·저장·재시도에 `open` 상태를 포함한다. 재시도하면 웨이브 시작 시점의 상태로 복원한다.

**새 동사**: «웨이브 중에 길을 바꾼다.» 굴착체가 뚫는 레인을 닫고 박격포 앞 레인을 연다. 보스를 긴 쪽으로 돌린다. 미로+박격포 전략에 **조작 보상**이 생긴다. 기존 소나·용접은 «숫자에 쓰는» 액티브였지만 이것은 «배치에 쓰는» 액티브다.

**보이는 것**: 열림·닫힘에 따라 수문 실루엣이 달라진다(판이 내려감/올라감). 선택 트레이에 48px 토글 버튼과 쿨다운 원호를 둔다. 토글 즉시 경로 화살표(pathHint)가 갱신된다. M2 수정의 «고스트 기준 배치» 규칙을 따라 타일을 가리지 않는다.

**계약 추가**: `BuildingId |= 'floodgate'` · `SimCommand |= { kind: 'toggleGate'; tile }` · `BuildingView.open: boolean`(수문 외 false) · `RejectReason |= 'gateCooldown'` · `SimEvent |= { kind: 'gateToggled'; tile; open }` · `RunSave.buildings[].open?`

**함께 고칠 것(G3 잔여)**: `deepArchaeology` 보상 문구를 실제 효과와 맞추거나 `abilityCooldownScale`을 `sim.ts:323` 쿨다운 설정에 연결한다. 연결을 권장한다. 문구가 약속한 효과다.

### 4.4 [4순위, 다음 라운드] 선체 판 운반 — 스케치만

`deepArchaeology` 발견 후 잠수정이 잔해 옆에서 **선체 판 1장**을 집는다. 조명 안 빈 타일에 투하하면 그 웨이브 동안만 존재하는 임시 격벽이 된다. 이동 중 «운반» 상태를 쓰므로 새 버튼이 필요하다. **360×640 독에 세 번째 액티브 버튼을 둘 공간이 없다**는 UI 위험이 있어 이번 마일스톤에서 뺀다.
