# 검증 계획과 완료 기준

## 문서 단계

1. 설계 작성: 게임 기획과 기술·아트 기획을 서로 다른 Claude Opus high 작업자가 작성한다.
2. 교차 검토: 서로의 문서를 읽어 모순·누락·구현 위험을 기록하고 자신이 소유한 문서의 해결 가능한 문제를 수정한다.
3. 독립 검증: 별도 Claude 작업자가 전체 문서를 검토한다. 심각한 미해결 문제는 구현 진입을 막는다.
4. 코디네이터 검증: 실제 경로·링크·Git 격리·요구사항 커버리지를 확인한다.

이 단계에서는 실행 가능한 코드가 없으므로 전투 재미·성능·서버 용량·보안이 검증됐다고 말하지 않는다.

## 구현 단계 진입 후 증거

|단계|필수 증거|실패하면|
|---|---|---|
|전투 실험|동일 조건에서 단순 입력/분기 콤보 비교, 보상 제거 후 재플레이 의향, 피로·판독 실패 기록|전투 재설계, 콘텐츠 대량 제작 중단|
|온라인 전투|2~4 클라이언트, 지연·손실 주입, 입력/판정 불일치와 서버 틱 측정|예측·판정 규칙 수정|
|온라인 절편|마을→파티→퀘스트→보스→보상→포탈→제작을 실제 클라이언트로 완료|흐름·상태 계약 수정|
|경제 신뢰성|중복 요청·프로세스 종료·재접속·구매 재통지에서 중복 지급/유실 없음|출시 차단|
|공용 마을|목표 인원에서 서버·클라이언트 프레임 시간, 트래픽·채팅 측정|인원/표현량 조정|
|아트 파이프라인|실제 리깅 캐릭터의 공격·회피·피격·사망 전환, 관통·발 미끄러짐·무기 부착 검수|스켈레톤/웨이트/클립 교정|
|출시 후보|빌드·타입 검사·핵심 테스트·복구 훈련·신고 처리·권한 검증|해당 위험 해결 전 출시 보류|
