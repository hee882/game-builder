## 사용자 요구

- 3D 액션 RPG. 전투 타격감과 사냥 자체의 재미가 핵심.
- 키보드 입력·콤보와 화려하지만 읽히는 스킬, 전설 무기·아이템 조합.
- NPC가 큰 이야기 속에서 미션을 주고 중간보스와 보스로 진행.
- 타운포탈, 멀티플레이, 채팅, 낯선 사람 수십 명이 보이는 온라인 공간.
- 별도 이름과 격리된 하위 프로젝트. 컨셉·시놉시스·시나리오·퀘스트·기술·디자인·아키텍처를 먼저 문서화.
- Claude Opus high 다중 작업자를 통한 설계·교차 검토·수정·구현·독립 검증.

## 범위 경계

첫 절편에는 무기 1종, 차별화된 일반 적, 중간보스·보스, 작은 마을과 던전, 퀘스트·제작·포탈의 한 바퀴를 검증한다. 전체 시나리오 및 다수 전설 무기는 출시 구상이며 첫 구현 범위와 다르다. 길드전·거래소·PvP·모바일 동시 출시·월드보스는 초기 필수 범위가 아니다.

## 저장소와 승인 경계

독립 저장소 `services/yeonmu`, 공통 기반 `vendor/game-builder` 고정 커밋 참조. 상위 저장소는 유지한다. 원격 게시·상용 서비스 구매·스토어 등록을 수행하지 않았다. 단계 0 승인 뒤 `npm run check`·`npm test`·`npm run build`와 오프라인 앱을 추가했다. 과거 문서 검증과 현재 코드 검증은 구분하며, 실제 증거와 미실시 게이트는 [단계 0 구현 보고서](p0-implementation-report.md)를 따른다.

## 충돌 처리

### 검토용 제안과 승인 상태 (2026-11-07)

다음은 문서 정렬을 위한 코디네이터 제안이며 **사용자가 승인한 요구사항이 아니다**. `[지정]`도 이 의미로만 해석한다. 구현 착수나 수치 확정 승인을 뜻하지 않는다(X14 출처 기록).

- 30Hz 패링 최소 5틱, 재접속 보호 3초: 현재 검토 기준이며 실제 플레이·지연 실험 후 재검토한다.
- 포탈 기름: 논리 전환당 1회 차감, 일시적 재시도 추가 차감 없음, 최종 실패 1회 반환. 커밋과 반환은 상호 배타적으로 처리한다는 제안이다.
- 주간 이월: 캐릭터 생성 및 변이 해금 이후 자격을 갖춘 주에만 적용한다는 제안이다.
- 환도 클립: 전투 27개와 전용 이동 1개를 구분하고 합계 28개를 상한 30개와 비교한다. 최종 동결은 후속 수정의 독립 재검증 이후 기록한다.

성능·재미·지연 상한 및 비용은 실측 전이다.

이 기록은 사용자 요구와 제안 상태의 기준이다. 게임 세부 규칙은 design 문서, 시스템 계약은 technical 문서가 소유한다. 교차 검토에서 불일치는 양쪽 소유자가 수정하고 검토 기록에 해결 여부를 남긴다. 외부 서비스의 지원 기능·가격·라이선스는 구현 직전 공식 자료와 실제 연결로 재확인한다.
