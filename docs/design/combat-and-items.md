## 3. 타이밍 제안 <a id="timing"></a>

### 3.0 단위와 환산 규칙 <a id="tick-units"></a>

- **구현 데이터의 단위는 30Hz `actionTick`(1틱 ≈ 33.3ms = 60fps 2f)** 이다. 아래 표의 **틱 값이 전투 데이터(`content/combat/*.json`)의 디자인 원천**이며, 괄호 안 ms·60fps 프레임(f)은 의도를 설명하는 참고값이다. [제안] (v0.1은 60fps 프레임이 원천이었다 — 교차 검토에서 틱 원천으로 전환. 근거: [design-cross-review D-01](../production/design-cross-review.md#d-01))
- 환산 규칙은 technical [architecture §9.5](../technical/architecture.md#95-60fps-디자인-값--30hz-틱-변환제안)와 같다. 요약: **플레이어의 창(입력 버퍼·판정 활성·캔슬·박자·튕겨내기·회피 무적)은 바깥쪽으로 넓히고, 플레이어의 약속(선딜·동작 끝)은 짧게, 적 텔레그래프 리드타임은 올림, 적 판정 구간은 좁게, 히트스톱은 올림.** [제안]
- **튕겨내기 활성 창은 30Hz에서 최소 5틱**(167ms)이며, 어떤 변이·잔향구·옵션도 이 하한을 깨지 않는다. [지정]
- 서버 전투 틱이 60Hz가 되면 모든 틱 값을 2배로 한다. 30Hz 미만으로 낮추는 변경은 이 변환 표를 디자인·기술이 재검토·합의하기 전에는 하지 않는다(architecture §7.1과 합의). 이 표는 사용자 승인값이 아니라 교차 검토 합의 [제안]이다(튕겨내기 5틱 하한만 [지정]).

### 3.1 시계 귀속 — 무엇이 히트스톱에 멈추나 <a id="clocks"></a>

architecture [§9.2](../technical/architecture.md#92-세-개의-시계)의 세 시계에 디자인 타이머를 배정한다. [지정: 행동 타이밍 창은 actionTick, 히트스톱은 공격자 타임라인 정지 / 제안: 나머지 배정]

| 타이머 | 시계 | 히트스톱 중 |
|--------|------|-------------|
| 입력 버퍼, 박자 분기 창, 캔슬 창, 판정 활성, 선딜·후딜, 콤보 리셋 | 그 플레이어의 `actionTick` | **멈춤** |
| 튕겨내기 창, 회피 무적, 완벽 회피 판정, 막기 선딜 | 방어자의 `actionTick` | 멈춤 (방어자에게 유리하게 길어짐) — 단 아래 규칙 3 |
| 적·보스의 공격 타임라인과 텔레그래프 리드타임 | `serverTick` | **멈추지 않음** (규칙 2) |
| 적 피격 경직 (§3.2) | `serverTick` 상태 | 히트스톱과 별개 규칙 |
| 기술 쿨다운, `잔영` 1.2초, 잔향구 지속 효과, 기세 감쇠 창 | `serverTick` | 흐름 |
| 이름 부르기 4초, '분이' 응답 3초 정지, 쓰러짐 15초·일으키기 3초, **재접속 보호 3초**, 잔상 전환 5초, 좌석 예약 180초, 귀로등 시전 3초·돌아오는 문 60초 | `serverTick` (초 × 30틱) | 흐름 |
| 화면 흔들림, VFX, 애니메이션 재생 | 클라이언트 표현 시간 | 연출 데이터대로 |

**규칙** [제안]

1. **히트스톱은 피해량·명중 여부를 바꾸지 않는다.** 대신 공격자의 `actionTick`을 멈추므로 공격자의 다음 동작은 서버 틱상에서 그만큼 늦게 온다. 서버와 클라이언트가 같은 틱 데이터로 같은 양만큼 멈춘다. 한 히트 프레임에 여러 대상을 맞히면 정지량은 합이 아니라 최댓값 1회(architecture §9.3-1). — v0.1의 "판정에는 영향 없음"을 이 문장으로 대체한다.
2. **적·보스의 타임라인은 플레이어 히트스톱으로 멈추지 않는다.** 4인이 연타해도 보스 패턴의 박자와 예고 소리·리드타임이 인원수와 무관하게 일정해야 하기 때문이다. 피격된 적의 '멈칫'은 표현에서만 보인다. 일반 적을 멈추는 수단은 피격 경직(게임 규칙)이며, 슈퍼아머가 있는 적에게는 걸리지 않는다. (architecture §9.3-2 제안 수용)
3. **방어 입력(회피·튕겨내기)은 자기 히트스톱의 남은 정지를 즉시 끝낸다.** 내 공격의 히트스톱 때문에 방어 시작이 늦어지지 않게 하기 위해서다. 따라서 튕겨내기 창은 `serverTick`으로 세어도 최소 5틱이 보장된다. → technical 반영됨(architecture §9.3, delivery P0-T4 — [X-D1](../production/design-cross-review.md#x-d1))
4. **화면 전체 정지형 히트스톱은 쓰지 않는다**(1인 인스턴스 포함). 히트스톱은 공격자 타임라인과 각 엔티티의 표현에만 적용한다.
5. 피격자가 플레이어일 때는 표현만 멈칫하고, 행동 제한은 피격 경직 데이터가 처리한다.

### 3.4 튕겨내기·막기 입력 해석 (같은 키의 탭/홀드) <a id="guard-input"></a>

서버는 누르는 순간 탭인지 홀드인지 알 수 없으므로, 다음 규칙으로 정한다. [제안]

1. 막기 키를 **누른 틱 = 튕겨내기 0틱째**. 5틱 창이 바로 열린다.
2. 창 안에서 성공하지 못했을 때, **창이 끝나기 전에 키를 뗐으면** 실패 후딜 10틱.
3. **창이 끝날 때 키를 아직 누르고 있으면** 실패 후딜 없이 막기 활성으로 바로 넘어간다(막기 선딜 생략). 이후 피격은 막기 게이지만 깎는다.
4. 토글 옵션: 첫 누름 = 튕겨내기 + 이어서 막기, 두 번째 누름 = 막기 해제.

의도: "누른 채 버티기"는 막기 게이지로, "연타"는 실패 후딜로 각각 대가를 치른다. 홀드가 항상 이득인지 [C3](#combat-gates) 텔레메트리로 확인한다. technical은 이를 `pressEdges`/`releaseEdges`로 판정한다(architecture §7.4).

|--------------|------------------------------------------|-----------|
| 일반 적 약공 | 12틱 | 400ms |
| 일반 적 강공·잡기 | 18틱 | 600ms |
| 보스 단일 대상 | 18틱 | 600ms |
| 보스 광역 (빨강) | 24틱 | 800ms |

| 같은 적의 연속 노랑(튕겨내기 가능) 타격 간격 | ≥ 12틱 | 튕겨내기 성공 히트스톱 4틱 뒤에도 다음 창을 열 여유 |

- 이 값은 **서버 데이터 기준**이다. 원격 보간·편도 지연만큼 화면에서는 늦게 보이며, 그 차이는 technical의 방어자 기준 보류 판정(architecture §10.2)이 상한 안에서 보상한다. 상한을 넘는 지연의 체감 리드타임은 [C9](#combat-gates)·[C12](#combat-gates)로 측정한다.

**즉사 공격 없음** — 절편의 어떤 단일 공격도 기본 방어구 기준 최대 체력의 60%를 넘지 않는다. [제안]

### 3.6 온라인 요구사항 (technical에 요청)

- 내 입력의 **반응(애니메이션 시작)은 로컬에서 즉시** 보여야 한다. 목표: 입력 → 첫 프레임 표시 ≤ 50ms (로컬). [가정, 측정 필요]
- 튕겨내기·완벽 회피 판정은 **방어자에게 유리하게**(플레이어 화면에서 창이 열려 있었으면 성공) 처리한다. 판정 조건은 "적 판정 틱이 방어자 화면 기준으로 방어자의 창(최소 5틱) **안**에 있을 것" — 창의 시작과 끝을 모두 검사한다. 허용 상한·악용 방지는 technical 결정(architecture §10, 초기안 200ms). ([concept A3](concept.md#assumptions))
- **히트스톱 동안 콤보 창·박자 창은 흐르지 않는다**(§3.1). 디자인 의도는 "히트스톱이 길어도 박자 분기가 같은 손감각으로 나간다"이다.
- 고지연 시 튕겨내기 창 **자동 확대는 하지 않는다**(architecture §10과 합의). [§5.2](#accessibility)의 '튕겨내기 창 +50%(5→8틱)'는 플레이어가 직접 켜는 접근성 옵션이며, 자기 창에만 작용하는 PvE 보조이므로 **파티 콘텐츠에서도 허용**한다. [제안]

### 4.5 애니메이션 예산 — 콤보 노드별 <a id="anim-budget"></a>

전투 클립은 판정 틱(§3.3)과 1:1로 맞춰 수작업 또는 대폭 수정해야 하므로(art §7.3) 가장 비싼 자산이다. 클립 **수량 집계와 제작 방식은 art 소유**([art §10.1](../technical/art-and-animation.md#101-콤보별-애니메이션-예산첫-절편)), **노드별 비용 등급(`animCost`)과 상한은 디자인 소유**로 나눈다. 모든 수량은 측정 전 [제안]이며 S-A2 실측(등급별 클립당 제작 시간)으로 조정한다.

**디자인 상한** [제안]

1. **콤보 노드 1개 = N 등급 최대 1개**(차지·홀드형 노드만 시작·루프·해제 3개).
2. 동작 변화는 D → R → P → N 순으로 먼저 시도한다. R 허용 폭은 art §10.1(재생 속도 ±25%, 루트 이동 ±30%)을 따른다. N은 "동작이 바뀌었다"([C5 원칙](#1-전투-원칙)·[C10](#combat-gates))로 읽히지 않을 때만.
3. **잔향구 1종당 N 최대 2개**(교체 노드 1 + 해방기 1). 출시 6종 → 최대 12.
4. **T2 각인은 첫 절편 2종으로 제한**하고 각 N 최대 1개 — art X10 질문에 대한 디자인 답.
5. **무기 1종당 전용 클립 상한 30개.** 무기 전용 = 이름에 무기 ID가 들어가는 클립(`*_hwando_*`). 공통 클립(`*_common_*`: 회피·지침·피격·공통 이동·시스템)은 넣지 않는다. 환도 집계 규약 [제안]:
   - **환도 전투 클립 소계 27** = 콤보 노드 16 + 기술·해방 5 + 환도 방어 6(art §10.1 '전투' 행과 같은 범위, 공유 규약으로 유지).
   - **환도 전용 이동 `loco_hwando_run` 1**은 전투 소계 밖에서 따로 세지만 무기 상한에는 들어간다.
   - **환도 전용 합계 28 ≤ 30.** 문서에서 '27'은 항상 **환도 전투 클립 소계**, '28'은 **무기 상한과 대조하는 환도 전용 합계**다(art §10.1 표에서는 플레이어 전체 표 안의 '환도 전용 소계' 행이 이 28이다). 공통 이동 4(`loco_common_*`)는 무기 상한에 넣지 않는다(art §10.1과 같은 공유 규약, 독립 검증 F-10).
6. 클립 판정 마커(`active`, `hit`, `cancel_window`, `beat_delay_window`, `hitstopTicks`)의 원천은 §3.2~3.3 틱 표다. 사이드카 값이 다르면 빌드 실패(art §8.4).
7. 새 노드·잔향구·각인을 제안할 때 디자인 데이터에 `animCost`를 함께 적는다(art X10 수용).

## 5. 가독성과 접근성

### 5.1 가독성 — "화려하지만 읽히는" [요구 → 제안]

| 규칙 | 내용 |
|------|------|
| **3중 부호화** | 적 공격 예고는 **색 + 무늬 + 소리** 셋으로 동시에 알린다. 색만으로 구분하지 않는다. |
| 빨강 | ✕ 빗금 무늬 · 낮은 징 소리 → **막기·튕겨내기 불가, 회피** |
| 노랑 | ◇ 테두리 섬광 · 방울 소리 → **튕겨내기 가능** |
| 보라 | 물결 무늬 장판 · 낮게 깔리는 곡소리 → **머물면 피해, 이동** |
| 흰 깜빡임 | 손 모양 무늬 · 천 찢는 소리 → **잡기, 회피 또는 기합** |
| 렌더 우선순위 | 적 예고 > 내 캐릭터 > 적 > 파티원 효과 > 내 효과 장식 |
| 파티원 효과 | 기본 불투명도 50% (옵션 0~100%) |
| 내 효과 | 화려하게. 단 적 예고 영역과 겹치면 자동으로 30%까지 투명화 |
| 피해 숫자 | 기본 '중요만'(치명·가드 브레이크·관통). 전체/끔 선택 |
| 가림 | 벽·지붕 뒤 캐릭터와 적은 실루엣 표시 (쿼터뷰 필수) |
| 사망 원인 | 사망 화면에 마지막 피격 공격 이름 + 예고 색 표시 ([G4](concept.md#gates)) |

> **예고 색 의미의 원천은 이 표다.** 플레이어가 취할 행동(회피·튕겨내기·이동·잡기 대응)을 정하는 게임 규칙이기 때문이다. art §4.2 v0.1 표(붉은 = 회피 가능 범위, 보라 = 패링 불가 공격)와의 충돌은 art v0.2에서 이 표로 교체되어 해소됐다. 외형 상품·잔향구 외형은 이 네 색·무늬를 쓸 수 없다(art §4.2·delivery §5.1과 일치).
> 렌더 우선순위상 **적 예고가 내 캐릭터보다 위**다(art §4.1 v0.2와 일치). art §1.3의 '판독 우선순위'(내 캐릭터 1, 적 위협 2)는 캐릭터 실루엣 밝기 순위로 읽는다 — 문구 정렬은 [X-A2](../production/design-cross-review.md#x-a2).

### 6.2 보스 설계

#### 되돌이 삿갓 (중간보스, [Q-M04](quests.md#q-m04))

- **핵심 장치 — 흉내:** 각 플레이어가 최근 30초 동안 가장 많이 쓴 콤보 경로를 기록. 같은 경로를 **3회 반복**하면 삿갓이 손뼉을 치고(소리 + 노랑 테두리), 그 플레이어가 그 경로를 다시 시작하는 순간 **예측 반격**한다.
- 다른 경로를 쓰면 흉내는 풀린다. "반복하는 버릇"을 직접 벌하는 보스 — 이 게임의 반(反)반복 철학을 전투로 가르친다.
- **2페이즈 (체력 50%):** 흐릿한 분신 2개가 **플레이어가 직전에 한 동작을 그대로 재연**하며 공격. 내 동작을 내가 피하는 구조.
- 파티: 흉내는 플레이어별로 따로. 한 사람이 흉내 대상이 되면 다른 사람이 공격 기회를 얻는다.

#### 곡비 어멈 (보스, [Q-P01](quests.md#q-p01)) <a id="boss-gokbi"></a>

| 페이즈 | 체력 | 패턴 | 예고 | 정답 / 가르치는 것 |
|--------|------|------|------|-------------------|
| 1 **곡(哭)** | 100~70% | 울음 파동 — 확장하는 고리 | 빨강 | 고리를 **회피로 통과** (뒤로 도망치면 다음 고리에 맞음) |
| | | 소매 휘두르기 2연 | 노랑 | **튕겨내기** → 되받아 베기 |
| | | 상복 천 잡기 | 흰 깜빡 | 회피 / 기합 |
| 2 **상여** | 70~35% | 상여꾼 잔향 4명이 상여를 메고 경기장을 돌며 길을 막는다 | 상여 소리 | 상여 앞 꼭두 장식을 치면 상여 정지 |
| | | 곡소리꾼 2마리 소환 | 보라 | 일섬·돌진 찌르기로 처리 |
| | | **울음 3연** — 고리 3개가 *장단*에 맞춰 퍼짐 | 빨강 | 박자 분기에서 배운 리듬으로 회피 ([Q-T01](quests.md#q-t01)과 연결) |

- **분노 타이머 없음** (절편). 실력 대신 시간으로 압박하지 않는다.
- 최대 단일 피해 ≤ 최대 체력 60%.
- **이름 부르기 대상 선정:** 접속 중이고 쓰러지지 않았으며 재접속 보호 중이 아닌 참가자 중에서 고른다. 자격자가 대상 수보다 적으면 대상 수를 줄인다. 대상이 4초 안에 끊기면 강타는 그 자리에 그대로 떨어진다(끊긴 캐릭터는 이미 피격 대상이 아니므로 피해 없음). [제안]

### 6.3 인원수 스케일링과 보스 기여 <a id="scaling"></a>

| 인원 | 보스 체력 | 일반 적 수 | 곡비 소환 수 | 이름 부르기 대상 | 쓰러짐 처리 |
|------|-----------|-----------|-------------|-----------------|-------------|
| 1 | ×1.0 | ×1.0 | 2 | 1 (항상 나) | 문 앞 등불에서 부활, 보스 초기화 |
| 2 | ×1.7 | ×1.5 | 2 | 1 | 15초 안에 동료가 3초 일으키기 |
| 3 | ×2.4 | ×2.0 | 3 | 2 (동시) | 동일 |
| 4 | ×3.0 | ×2.5 | 4 | 2 (동시) | 동일 |

**인원 산정** [제안]

- 보스전의 **인원 = 교전 시작(보스방 문이 닫히는 틱)에 보스방 안에 있는 좌석 보유자 수.** 이 인원이 그 교전 시도의 **참가자 명단**이다.
- 교전 중 배율은 고정한다. 참가자가 끊겨 재접속 예약(180초) 중이어도 배율은 그대로다.
- **예약이 만료돼 좌석이 해제되면** 보스의 남은 체력 **비율을 유지한 채** 새 인원 배율로 다시 계산한다. 소환 수·이름 부르기 대상 수는 다음 페이즈 전환부터 새 인원을 따른다. 일부러 끊어 체력을 낮추는 이득은 없다 — 끊긴 사람은 좌석과 함께 크레딧을 잃는다.
- 교전 시작 전에 끊겼거나 귀로등으로 나가 있던 사람은 참가자가 아니다. 돌아오면 보스방 문 앞(체크포인트 C)에서 교전이 끝나기를 기다린다(신규 입장 차단, [quests §2.3](quests.md#reconnect)).

**쓰러짐·전멸** [제안]

- 2인 이상에서 15초 안에 일으켜지지 않으면 **혼백(관전)** 상태로 보스방 안에 남는다. 혼백은 공격받지 않고, 교전이 이기면 기여 조건에 따라 크레딧을 받는다.
- **접속 중인 참가자 전원이 쓰러짐 또는 혼백이면 전멸** → 보스 초기화, 전원 문 앞 등불(체크포인트 C)에서 부활. 끊긴 참가자(잔상)는 생존으로 세지 않는다.
- **2인 이상 공통:** 같은 사람을 같은 교전 시도에서 다시 일으킬 때마다 일으키기 시간이 1초씩 늘어난다(3초 → 4초 → 5초…, 보스 초기화 시 리셋). v0.2 초안 표에는 3인 행에만 적혀 있었으나 인원 무관 규칙이다(architecture §12.4와 일치, 독립 검증 F-08).
- 일으키기 3초(+회당 1초)·쓰러짐 15초는 `serverTick` 타이머(§3.1).

**보스 기여 (크레딧 조건)** [제안] — 판정 이벤트 단위로 서버가 기록하고, 보스 초기화 시 지운다.

| 기여로 인정 | 서버 근거 이벤트 |
|-------------|-----------------|
| 확정 피해 1회 이상 (보스·소환물·상여·꼭두 장식 포함) | `HitConfirmed` |
| 보스 또는 그 소환물의 공격을 튕겨내기 1회 | `DefenseResolved{parried}` |
| 쓰러진 참가자 일으키기 완료 1회 | 일으키기 완료 이벤트 |
| '분이' 응답 1회 | 응답 상호작용 이벤트 |

크레딧 = 처치 틱에 **좌석 보유자(접속 중 또는 재접속 예약 중)이고 이번 교전 시도에서 기여 1회 이상**. 보상 지급 방식은 [quests §2.2](quests.md#party-rules). 문턱을 낮게 둔 이유: 낯선 사람을 도운 사람이 손해를 보지 않게 하고, 신규 입장 차단으로 '막타 무임승차'는 이미 막혀 있기 때문.

목표 클리어율: 1인 첫 시도 20~40%, 4인 3회 이내 ≥ 70% ([§10 C8](#combat-gates)).

## 7. 잔향구 — 동작을 바꾸는 전설 6종 <a id="legendaries"></a>

**규칙** [제안]

- 잔향구는 **같은 등급 일반 장비와 기본 수치가 같다.** 차이는 동작뿐.
- 각 잔향구는 **1절**(기본 동작 변화)과 **2절**(T4 승화, 도전 과제로 해금)을 가진다.
- 모든 잔향구에는 **대가**가 있다 — 무언가를 얻으면 무언가를 잃는다. 그래서 장착은 "업그레이드"가 아니라 "스타일 선택".
- 동시 장착: 첫 절편 1개, 출시 2개. 같은 노드를 두 잔향구가 바꾸면 **무기 > 장신구 > 방어구(머리·몸·손목·신발)** 우선이며, 장착 전 UI에 충돌을 표시한다.
- **장착·교체는 비전투 공간(마을, 개인 수련장)에서만** 한다. T2 각인 교체도 같다. 전투 인스턴스 안에서는 콤보 그래프가 바뀌지 않는다 — architecture §7.5의 "전투 중 금지 여부" 질문에 대한 디자인 답. [제안]
- 잔향구의 프레임 표기는 §3.0 환산 규칙을 따르며, 아래 값은 30Hz 틱으로 적는다.
- 마을에서 **외형으로 드러난다** — 낯선 길손이 무엇을 쓰는지 보이는 것 자체가 사회적 동기.
- 출처 보스와 세계 규칙: 물건에 깃든 잔향이 생전 몸놀림을 물려준다 ([narrative W4](narrative.md)).

## 8. 제작과 레시피 진행 <a id="crafting"></a>

### 8.1 장비 슬롯과 등급

- 슬롯: **무기 · 머리 · 몸 · 손목 · 신발 · 장신구**
- 등급: **일반(T0) → 장인(T1) → 잔향구(T3)**. T2는 등급이 아니라 개조(각인), T4는 잔향구 승화.

### 8.2 장인 등급 (강막쇠 신뢰도)

| 단계 | 해금 | 할 수 있는 것 | 재료 예 | 범위 |
|------|------|--------------|---------|------|
| **T0 기본** | 시작 | 상점 장비 | — | 절편 |
| **T1 장인** | [Q-S01](quests.md#q-s01) | 환도·방어구 T1 제작 (+10% 위력·방어, 유일한 수치 상승) | 녹슨 철편, 무명천 | 절편 |
| **T2 개조(버릇 각인)** | [Q-S02](quests.md#q-s02) | 콤보 노드 1개에 **작은 동작 변형** — 수치 없음. 마을에서 무료로 교체 가능 | 억새 줄기, 잔향 조각 | 절편 |
| **T3 잔향구** | [Q-M05](quests.md#q-m05) | 잔향구 제작 | 보스 기억 + 공명석 + 지역 재료 | 절편 |
| **T4 승화** | [Q-S06](quests.md#q-s06) | 잔향구 2절 | 도전 과제 달성 증표 + 이름패 조각 | 1막 출시 |

**T2 버릇 각인 예시:** `마무리 횡베기 → 2연 베기로` / `일섬 차지 0.6초 → 0.45초, 돌진 거리 −30%` / `흘려베기 → 뒤로 빠지며 베기` / `회전 베기 → 끌어당기는 회전`. 각 각인은 §1의 C5 원칙대로 **동작을 바꾸되 위력을 올리지 않는다.**

### 8.3 재료

| 재료 | 출처 | 귀속 | 용도 |
|------|------|------|------|
| 녹슨 철편 | 억새벌 개인 채집 노드 | 귀속 | T1 |
| 무명천 | 억새 잔향·곡소리꾼 드랍, 상점 | 귀속 | T1, 잔향구 |
| 억새 줄기 | 억새벌 채집 | 귀속 | T2, 잔향구 |
| 잔향 조각 | 모든 잔향 적 (일반 드랍) | 귀속 | T2 각인 |
| **공명석** | 중간보스·보스 **첫 처치 확정 1개**, 주간 변이 첫 클리어 1개 | 귀속 | 잔향구 |
| **보스 기억** | 보스 **첫 처치 확정**. 재처치 시 '기억 결' 1개(3개 = 기억 1개, 확률 없음) | 귀속 | 잔향구 |
| 울음의 재 | [Q-M05](quests.md#q-m05) '풀어 준다' 선택 | 귀속 | 곡비 기억 대체재 |
| 이름패 조각 | 조사 퀘스트(가온) | 귀속 | 잔향구(1막 이후), 승화 |
| 동행 공적 | 도우미 보상 ([quests §2.2](quests.md#party-rules)) | 귀속 | 공명석·재료 교환 |

> 거래소가 없으므로 첫 절편 재료는 **모두 귀속**. 거래 도입 여부는 [concept §9](concept.md#scope-out)대로 별도 결정.

**인벤토리 용량 (첫 절편)** [제안 — architecture X13 답]

- 재료·소모품·화폐(동행 공적 포함)는 종류당 1칸, **수량 상한 없음**. 이유: 재료가 넘쳐 보상을 못 받는 상황을 만들지 않는다.
- 장비·잔향구 같은 고유 아이템은 **30칸**. 절편에서 얻는 고유 아이템은 이보다 훨씬 적다(추정, 측정 전).
- 칸이 모자라 들어가지 못한 보상은 사라지지 않고 **보관함**에 쌓이며, 마을에서 언제든 꺼낸다(technical `reward_overflow`). 보관함 상한은 두지 않는다.

### 8.4 레시피 발견

- 잔향구 레시피는 **해당 보스와 처음 마주친 순간 공개**된다(져도 공개). 목표가 보이면 다시 도전할 이유가 생긴다.
- 레시피북에는 실루엣 + "어디서 기억을 찾을 수 있는가" 힌트를 표시.
- 가온의 문서, 막쇠의 신뢰 대사로 T2 각인 레시피가 열린다 — **발견이 새 행동을 연다.**

### 8.5 실험 비용을 낮춘다

- 잔향구 **해체 시 기억·공명석 전액 반환**(지역 재료만 소모). T2 각인은 마을에서 무료 교체.
- 이유: 잔향구는 스타일 선택이므로, 바꿔 보는 데 벌이 있으면 안 된다.

## 9. 반복 파밍 방지 <a id="anti-grind"></a>

| 장치 | 내용 | 막으려는 것 |
|------|------|------------|
| **좁은 수치 폭** | 수치 상승은 T0→T1의 +10%뿐. 잔향구·각인·승화는 수치 없음 | 숫자를 위한 반복 |
| **첫 처치 확정** | 보스 기억·공명석은 첫 처치에 반드시 | 확률 운에 막히는 진행 |
| **결정적 누적** | 재처치 '기억 결' 3개 = 기억 1개. 확률 드랍 없음 | 끝없는 재도전 |
| **필수 반복 0회** | 절편에서 첫 잔향구까지 같은 전투 공간 반복 불필요 ([quests §7](quests.md)) | 강제 반복 |
| **문 변이 (주간)** | 재도전 시 보스방에 변이 1개: ① 되돌이의 저주(같은 콤보 3연속 시 약화) ② 곡소리 장(정지 시 장판) ③ 무거운 안개(회피 거리 −30%, 튕겨내기 창 +1틱 = 6틱) ④ 갑주의 밤(일반 적 절반이 갑주귀) ⑤ 장단(박자 분기 피해 +30%) ⑥ 무명의 밤(잔향구 해방기 불가, 기세 충전 2배) | 같은 해법의 반복 |
| **기세 감쇠** | 같은 콤보 경로를 3회 연속 쓰면 그 경로의 기세 충전이 절반 (다른 경로 쓰면 즉시 회복) | 한 가지 콤보 고착 |
| **흉내 보스** | 되돌이 삿갓이 반복을 직접 벌함 | 한 가지 콤보 고착 |
| **동행 공적** | 낯선 사람을 도와도 공명석 교환 화폐를 얻음 | "도와주면 손해" |
| **일일 숙제 없음** | 주간 변이 보상은 누적형 — 놓친 주는 **최대 1주분** 이월해 다음 첫 클리어에서 함께 받음. 이월 대상은 캐릭터 생성·변이 해금 **이후의 자격 주**만([quests §7 원칙 6](quests.md#7-반복-콘텐츠-원칙-퀘스트-측면)) | 출석 의무감 |

측정: [concept G6](concept.md#gates), [§10 C4·C5](#combat-gates).
